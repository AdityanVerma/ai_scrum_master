# Phase 3 — Sprint Execution

Phase 3 was **Sprint Execution** — we took the sprint that the AI planned and made it **active, trackable, and progress-aware**.

---

## 1. Sprint Lifecycle

We added a status to every sprint:

```text
PLANNED
ACTIVE
COMPLETED
CANCELLED
```

This gives the sprint a proper lifecycle instead of being just a saved record.

The lifecycle is now:

```text
PLANNED
   ↓
ACTIVE
   ↓
COMPLETED
```

With `CANCELLED` available when a sprint needs to be stopped.

> **Current implementation note:** only `PLANNED → ACTIVE` is implemented (`activateSprint()` and `PATCH /api/sprints/[id]/activate`). `COMPLETED` and `CANCELLED` exist in the `SprintStatus` enum, but no API or UI moves a sprint into them yet.

---

## 2. Task Lifecycle

Every sprint task now has a status:

```text
TODO
IN_PROGRESS
DONE
BLOCKED
```

So individual tasks can now be tracked during the sprint.

---

## 3. Sprint Activation

We created the backend logic and API for activating a sprint:

```text
PATCH /api/sprints/[id]/activate
```

The system allows:

```text
PLANNED → ACTIVE
```

and rejects invalid activation attempts.

We tested this successfully against PostgreSQL.

---

## 4. Task Status Management

We created:

```text
src/lib/db/update-task-status.ts
```

with allowed status transitions.

For example:

```text
TODO → IN_PROGRESS
TODO → BLOCKED

IN_PROGRESS → DONE
IN_PROGRESS → BLOCKED
IN_PROGRESS → TODO

BLOCKED → TODO
BLOCKED → IN_PROGRESS

DONE → ❌
```

So the system doesn't allow arbitrary status changes.

We specifically tested:

```text
TODO → IN_PROGRESS → DONE ✅
```

and:

```text
DONE → TODO ❌
```

The second transition is rejected because a completed task cannot simply be moved back to `TODO`.

---

## 5. Task Status API

We exposed task updates through:

```text
PATCH /api/sprints/[id]/tasks/[taskId]/status
```

The API:

1. Receives the requested status.
2. Validates the requested transition.
3. Updates the task in PostgreSQL.
4. Returns the updated task.

This provides a controlled backend interface for task execution.

---

## 6. Sprint Progress Calculation

We created:

```text
src/lib/db/get-sprint-progress.ts
```

It calculates progress from the **actual database task statuses**, rather than anything generated by the AI.

For example:

```text
6 Tasks
2 Done
1 In Progress
2 TODO
1 Blocked
```

Progress is calculated as:

```text
Progress = Done Tasks / Total Tasks

         = 2 / 6

         = 33%
```

This means sprint progress always reflects the current execution state stored in PostgreSQL.

---

## 7. Sprint Progress API

We added:

```text
GET /api/sprints/[id]/progress
```

The API returns:

* Total Tasks
* TODO
* IN_PROGRESS
* DONE
* BLOCKED
* Progress Percentage

Example:

```text
Total Tasks: 6
TODO: 2
IN_PROGRESS: 1
DONE: 2
BLOCKED: 1
Progress: 33%
```

---

## 8. Sprint Execution UI

The sprint detail page now shows sprint progress:

```text
Sprint Progress                     33%

██████████░░░░░░░░░░░░░░░░

To Do          2
In Progress    1
Done           2
Blocked        1
```

Each task now also has an **interactive status dropdown**.

This means the sprint detail page is no longer just displaying information — it can now be used to execute the sprint.

---

## 9. Live Progress Updates

This was the final piece of Phase 3.

When you change a task status, for example:

```text
IN_PROGRESS → DONE
```

the system performs:

```text
Update PostgreSQL
       ↓
Update task on page
       ↓
Fetch latest progress
       ↓
Update progress bar
```

So you don't need to refresh the page.

The UI reflects the updated sprint progress immediately after the status change.

# Overall Phase Evolution

The system evolved through the first three phases as follows:

### Phase 1 — Persistence

> **"Save the sprint."**

```text
AI Sprint Planner
       ↓
Sprint Proposal
       ↓
PostgreSQL
```

### Phase 2 — Retrieval

> **"View the sprint."**

```text
PostgreSQL
       ↓
Retrieve Sprint
       ↓
Sprint History
       ↓
Sprint Detail
```

### Phase 3 — Execution

> **"Run and track the sprint."**

```text
Sprint
  ↓
Activate
  ↓
Track Tasks
  ↓
Calculate Progress
  ↓
Update UI
```
